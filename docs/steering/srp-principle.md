# 单一职责原则（SRP）规范

本项目遵循单一职责原则（Single Responsibility Principle, SRP）：每个模块、类和函数应当只有一个引起它变化的原因，只承担一项明确的职责。

## 核心规则

- 每个类只封装一项职责，避免出现同时处理多个不相关关注点的「上帝类」
- 每个函数/方法只做一件事，函数名应能准确概括其唯一职责
- 当一个模块因多种不同原因需要修改时，应拆分为职责单一的多个模块
- 领域逻辑、编排逻辑与基础设施逻辑必须分离，不得在同一单元内混杂（与 [ddd-architecture.md](ddd-architecture.md) 的分层约束保持一致）

## 判定信号（出现以下情况应考虑拆分）

- 类或函数的命名中出现 `And`、`Manager`、`Util`、`Helper` 等泛化词，暗示职责不清
- 一个函数体过长、包含多个独立的处理阶段，或需要大量注释分段说明
- 修改一处功能时频繁牵动同一文件中不相关的代码
- 单元测试难以聚焦，一个测试需要构造大量无关前置条件

## 实践建议

- 优先通过组合而非继承来复用职责单一的小单元
- Port/Adapter、领域服务、应用服务各自保持职责边界清晰，避免跨层承担额外职责
- 拆分后的每个单元仍须遵循 [code-documentation.md](code-documentation.md) 的 docstring 要求
