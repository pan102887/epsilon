# Dynamic Task Prompt Template Skeleton (v1)

> This file is for audit review only. It is not used for runtime string interpolation.
>
> The runtime system prompt is assembled in memory by
> `TaskAgentAdapter.build_system_prompt(task)` from structured `Task` fields. The
> runtime does not read this Markdown content and does not interpolate variables
> from it.
>
> This file records the current v1 section order and heading contract for code
> review and audit. The prompt registry only uses the corresponding `prompt_id`
> (`task-template@v1`) for traceability.

## Section Order

`TaskAgentAdapter.build_system_prompt` joins these sections with `\n\n`:

1. `<goal>`: the exact `task.goal` text, used as the primary instruction.
2. `## Input Data`: appended when `task.input_data` is non-empty. The body is `json.dumps(task.input_data, ensure_ascii=False, indent=2)`.
3. `## Constraints`: appended when `task.constraints` is non-empty. The body is a numbered list generated by `enumerate(task.constraints, 1)`.
4. `## Expected Output Format`: appended when `task.output_format is not None`. The body is the exact `task.output_format` text.

## Skeleton Example

```
<goal>

## Input Data
<JSON-serialized input_data>

## Constraints
1. <constraint_1>
2. <constraint_2>

## Expected Output Format
<output_format>
```

## Change Process

Changes to this skeleton must be committed together with:

1. A new `prompts/task-template/v<N+1>.md` file documenting the new skeleton.
2. The matching `TaskAgentAdapter.build_system_prompt` assembly code change.
3. A `config.properties` update that sets `PROMPT_TASK_TEMPLATE_VERSION=v<N+1>`.
